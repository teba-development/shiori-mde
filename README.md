# 栞（しおり） · shiori-mde

Windows向けのMarkdownエディタです。RustとTauri 2を使用し、x64とARM64のインストーラーとポータブル版を用意しています。

## 開く

インストール後はスタートメニューの「栞」から起動できます。`.md` の右クリックメニューで「プログラムから開く」を選び、「栞」を指定できます。既定にする場合は、アプリ選択画面で「常に使う」を選びます。

PowerShellからは、実行ファイルの最初の引数にMarkdownファイルのパスを渡します。相対パスは起動時の作業フォルダーが基準です。

```powershell
& 'C:\Apps\栞\shiori-mde.exe' 'C:\文書\読書メモ.md'
```

### ポータブル版

ZIPを書き込み可能なフォルダーに展開し、`shiori-mde-portable.exe` を起動します。起動時に作成される `app-data` フォルダーに、WebView2のプロファイルとキャッシュが保存されます。起動引数にも同じ形式でMarkdownファイルのパスを指定できます。

Microsoft Edge WebView2 Runtimeが必要です。ポータブル版で `.md` の既定アプリを指定する場合は、Windowsの「プログラムから開く」で展開した実行ファイルを選びます。

## 編集と保存

| 操作 | ショートカット |
| --- | --- |
| 新規作成 / 開く | Ctrl+N / Ctrl+O |
| 上書き保存 / 名前を付けて保存 | Ctrl+S / Ctrl+Shift+S |
| 表示 / Markdown編集＋プレビュー / WYSIWYG | Ctrl+1 / Ctrl+2 / Ctrl+3 |
| 文書内検索 / 次の一致 / 前の一致 | Ctrl+F / F3 / Shift+F3 |

- 表示モードではコードブロックの右上からコードをコピーできます。Markdown編集＋プレビューでは両側のスクロールが同期します。
- コードフェンスに `rust`、`python`、`js`、`json`、`sql`、`powershell` などの言語名を指定すると、本文が構文に応じて色分けされます。Markdown編集・プレビュー・WYSIWYGとHTML・PDF出力に対応しています。
- Markdown編集＋プレビューとWYSIWYGでは、コードブロック上部のプルダウンから言語を変更できます。選択結果はMarkdownに保存され、元に戻す操作にも対応しています。
- 言語の解析器は同梱しています。未指定・未対応の言語や、色分けの処理上限を超える大きなコードブロックは通常のテキストとして表示します。
- 見出しペインから本文の該当箇所へ移動できます。上部のペインアイコンで表示を切り替えます。
- 画像の相対パスはMarkdownファイルの場所が基準です。文書のフォルダー外を参照する場合は、ツールバーの「画像の参照フォルダーを許可」から画像のあるフォルダーを選びます。許可は開いている文書に対して有効です。
- 相対パスの画像がハードリンクの場合や、途中にシンボリックリンクやジャンクションがある場合は、「画像を挿入」から対象ファイルを直接選んでください。
- 別のフォルダーに名前を付けて保存すると、相対画像パスを保存先に合わせて調整します。新規文書や、文書フォルダー外から直接選んで挿入した画像は埋め込みます。
- 保存時はローカル画像の埋め込みとMermaid図のSVG化を個別に選べます。SVG化したMermaidブロックは、保存したMarkdownではSVG画像になります。
- PDFとHTMLは右上の「エクスポート」から出力します。HTMLにはローカル画像と描画済みのMermaid図が含まれます。
- ファイルの文字コードはUTF-8です。UTF-8 BOMとCRLFで統一された改行は保存時も維持します。WYSIWYGで本文を編集すると、Markdownの記法が整形される場合があります。
- 確認した保存先が同名の別ファイルに変わった場合は保存を中止します。保存中の競合で元の名前に戻せない場合は、元のファイルを同じフォルダーに退避して場所を表示します。
- 上書き時は元ファイルのWindowsアクセス権・整合性ラベルと代替データストリーム（ADS）を引き継ぎます。ADSの上限は合計64 MiB、256件です。上限を超える場合や元ファイルがEFSで暗号化されている場合は、書き込み前に上書きを中止します。元ファイルを退避した後と新ファイルの公開直後に所有者・アクセス権・整合性ラベル・ADSを照合し、不一致を検出した場合は元ファイルを復元します。
- 競合で元ファイルを復元できない場合も、保持する新ファイルへ元ファイルの最新の権限を適用します。適用できない場合は新ファイルへのアクセスを禁止して保全し、場所とエラーを表示します。この場合の取り出しには管理者による権限の復旧が必要になることがあります。
- 保存が中断されたときは、次回起動時に復元記録を使って文書本体とバックアップを確認します。文書本体を確認できない場合は一時ファイルを保持します。バックアップの削除前には本文とADSの内容、所有者、アクセス権・整合性ラベルを照合します。復旧後の編集などにより安全に削除できなくなったファイルは、保持した場所をまとめて通知します。通知の確認ボタンを押す前に終了した場合は、次回起動時にも表示します。
- Markdownは64 MiBかつ20万行まで、ローカル画像は1ファイル24 MiBまで、PDFとHTMLの出力は各64 MiBまでです。外部URLの画像はプレビューとエクスポートで代替テキストを表示します。

## 開発とビルド

WindowsにNode.js 24、RustのMSVCツールチェーン、Visual Studio Build Toolsの「C++によるデスクトップ開発」と必要なターゲットのMSVCコンポーネント、Windows SDK、Microsoft Edge WebView2を用意します。ARM64版にはARM64 C++ビルドツールが必要です。[TauriのWindowsビルド手順](https://v2.tauri.app/distribute/windows-installer/)

```powershell
npm ci
rustup target add x86_64-pc-windows-msvc aarch64-pc-windows-msvc
npm run test:frontend
cargo test --locked --manifest-path tools/frontend-fs/Cargo.toml
cargo test --locked --manifest-path tools/frontend-embed/Cargo.toml
npm run tauri dev
npm run build:x64
npm run build:arm64
npm run build:portable:x64
npm run build:portable:arm64
```

インストーラーは `src-tauri/target/<ターゲット>/release/bundle/nsis/` に生成されます。
ポータブル版の実行ファイルは `src-tauri/target/<ターゲット>/release/` に生成されます。
配布ファイルは [GitHub Releases](https://github.com/teba-development/shiori-mde/releases) から入手できます。ローカルで検証済みの配布ファイルは `release/` に配置します。

Microsoft Store向けには、本体のx64版・ARM64版を `npm run package:store` で1つのMSIXバンドルにまとめます。準備と提出の手順は [Microsoft Storeへの掲載](docs/microsoft-store.md) を参照してください。

フロントエンドはesbuildでビルドします。`npm run dev` は `http://127.0.0.1:1420/` で開発用サーバーを起動し、ソース変更を再ビルドします。再ビルド後にアプリを再読み込みすると反映されます。

フロントエンドのファイル操作にはRust製の補助ツールを使用します。初回にホストのx64またはARM64用に自動ビルドされるため、`npm run build` と `npm run dev` にもRustが必要です。HTML、TypeScript、CSS、PNGと `tsconfig.json` は、保持したWindowsハンドルを基準に読み込みます。ファイルごとにサイズを制限し、リンク経由の読み込みを拒否します。ビルドには信頼できるツールチェーンと依存パッケージを使ってください。

`npm run build` は一時フォルダーに生成したファイルの名前、サイズ、SHA-256を照合してから `dist` を置き換えます。開発サーバーでは生成物をメモリから配信します。公開ロックはハンドルが閉じられると自動で削除されます。旧版で残った `.frontend-publish.lock` や、強制終了で残った一時フォルダーは、他のビルドが使用していないことを確認してから削除してください。

配布物は上記4つのnpmビルドコマンドで作成します。生成物を1つのファイルにまとめ、コンパイラが保持したWindowsハンドルから読み取ります。コンパイラは配布スクリプトから受け取ったSHA-256を照合し、検証したバイト列をTauriのアセットとして直接埋め込みます。

同じCargo出力フォルダーを使う配布ビルドは、一方のインストーラー生成や実行ファイル配置が終わってから進みます。
配布ビルドはCargo出力フォルダー内の `.shiori-build-*` で作業します。PEの構造・セクション整列とWindowsによるイメージの読み込み、アプリ本体の対象アーキテクチャ、NSISの書式とCRC（有効時）を検証します。インストーラーに含まれるアプリを7-Zipで読み出し、今回生成したアプリにTauriのNSIS識別子を反映した内容とSHA-256で照合してから共有先を更新します。この検証には7-Zipが必要です。標準のインストール先を使うか、環境変数 `SHIORI_7ZIP` に `7z.exe` の絶対パスを指定してください。

インストーラーを抽出する7-Zipは、起動時にビルドと同じWindowsジョブに登録します。配置処理の成否にかかわらず全子プロセスの終了を確認してから作業フォルダーを再利用可能にします。監督プロセスが強制終了された場合は抽出ツールも終了し、中断した作業フォルダーは次のビルドで再利用しません。

次回のビルド開始時に中断した配置を復旧し、記録済みのIDと一致する準備用ファイルを片付けます。FATなどでIDを再利用し得るファイルシステムでは、準備用ファイルと記録を保持します。名前変更後の同一性を確認できない成果物と未完了の復旧記録も保持します。完了済みの配置の後片付けに失敗した場合は、次のビルドで再試行します。子プロセスの終了を確認した作業フォルダーは再利用できます。Tauriの `src-tauri/gen/schemas/` は、複数のCargo出力フォルダーからの同時生成を防ぐため、ビルドスクリプトがプロジェクト単位でロックします。
